# Методология аудита AI-видимости бренда

Цель аудита — измеримо ответить на вопрос: **как часто и в каком качестве бренд попадает в ответы ИИ-ассистентов, когда пользователь выбирает товар в его категории**, и что нужно изменить, чтобы попадать чаще.

Аудит состоит из четырёх блоков: пул запросов → замер SoV → анализ источников → план работ. Повторный замер по той же методике через 6–10 недель после внедрения — доказательство эффекта «до/после».

---

## 1. Пул запросов

Пул — это 30–80 формулировок, которыми реальные покупатели спрашивают ИИ о категории клиента. Пул фиксируется в конфиге (`queries.example.yaml`) и **не меняется между замерами** — иначе «до/после» несравнимы.

Запросы собираются по четырём типам (все четыре обязательны):

| Тип | Пример (категория «протеин») | Что проверяет |
|---|---|---|
| Категорийный шорт-лист | «Какой протеин лучше купить?» | Попадание в топ выдачи «с нуля» |
| Сценарный / под задачу | «Посоветуй протеин для набора массы новичку, бюджет до 3000 ₽» | Видимость в нишевых сценариях — здесь конкуренция ниже |
| Сравнительный | «X или Y — что лучше?» (бренд клиента против лидера) | Как ИИ описывает бренд рядом с конкурентом |
| Брендовый | «Стоит ли покупать протеин X? Какие минусы?» | Тональность и фактическую корректность знаний ИИ о бренде |

Источники формулировок: подсказки Яндекса/Google, Wordstat, вопросы на маркетплейсах и Яндекс Кью, отдел продаж клиента («какие вопросы задают перед покупкой»). Каждый запрос пишем разговорно, как в чат, а не как поисковый запрос из ключевых слов.

Для каждого запроса фиксируем 2–3 вариации формулировки — ответы ИИ чувствительны к фразировке, и вариации входят в пул как отдельные строки.

## 2. Протокол замера

Недетерминированность ИИ гасим повторами и статистикой, а не надеждой на «честный один прогон»:

- **Повторы:** каждый запрос — минимум 5 прогонов на каждой модели (для пилота; 10+ для продакшена). Один прогон ничего не доказывает.
- **Модели:** минимум по одной из каждого лагеря — YandexGPT (прокси Алисы), GigaChat, ChatGPT/глобальная модель. Замер и отчёт — в разрезе по моделям: рычаги влияния на них разные.
- **Чистые сессии:** каждый прогон — новый диалог, без истории, памяти и персонализации. Температура и параметры — дефолтные для провайдера (мы имитируем обычного пользователя, а не выжимаем детерминизм).
- **Честная оговорка в отчёте:** замер через API — приближение к ответам в пользовательских приложениях (там другой поиск и персонализация). Это ограничение фиксируется в методологии и показывается клиенту как есть; калибровку по реальным интерфейсам делаем выборочно вручную (10–20 запросов).
- **Всё сырьё сохраняется** (JSONL с полными текстами ответов): отчёт можно переаудировать, а тексты ответов — сырьё для анализа источников и тональности.

## 3. Метрики SoV

Считаются по каждому бренду (клиент + 3–7 конкурентов), в разрезе модель × тип запроса:

- **Mention rate** — доля прогонов, где бренд упомянут хотя бы раз. Основная метрика SoV.
- **Top-1 rate** — доля прогонов, где бренд назван первым среди брендов. «Первая позиция шорт-листа».
- **Средний ранг** — средняя позиция бренда среди упомянутых брендов (по порядку первого упоминания), только по прогонам, где бренд есть.
- **Тональность** (второй этап, вручную или LLM-judge) — по брендовым и сравнительным запросам: рекомендует / нейтрально / отговаривает.

«До/после»: сравниваем mention rate по биномиальному доверительному интервалу; для пилота достаточно правила большого пальца — при 5 повторах × 30 запросах на модель сдвиг mention rate меньше ~8 п.п. считаем шумом и не продаём как результат.

## 4. Анализ источников и план работ

Из сырых ответов (и отдельно — из режимов с веб-поиском, где модель показывает ссылки) выписываем, **кого ИИ цитирует и пересказывает** в категории: обзорники, «топ-10» статьи, Яндекс Маркет/Кью, Википедия, отраслевые СМИ, отзовики. Это и есть карта рычагов: ИИ не «покупается», но опирается на корпус источников, и присутствие бренда в топе цитируемых источников — главный управляемый фактор.

План работ в аудите приоритизируем по формуле «частота цитирования источника × достижимость для клиента»: 

1. источники, где бренд может появиться быстро (отзывы, Q&A, карточки маркетплейсов, обновление Википедии по правилам),
2. статьи-подборки и СМИ, куда можно попасть через PR/размещение,
3. сайт бренда: структурированные данные, FAQ-страницы с разговорными формулировками, доступность для краулеров ИИ (robots.txt не блокирует GPTBot/YandexBot и др.), llms.txt.

## Результат аудита (что получает клиент)

1. Таблица SoV: клиент vs конкуренты, по моделям и типам запросов.
2. Карта источников, на которые опираются ИИ в категории.
3. Фактические ошибки и негатив в ответах ИИ о бренде.
4. Приоритизированный план работ на 2–3 месяца с прогнозом по метрике.
5. Дата контрольного повторного замера (тот же пул, тот же протокол).
